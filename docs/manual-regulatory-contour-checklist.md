# Manual Regulatory Contour Checklist

Обновлено: 2026-03-12

Цель:
- не смешивать кодовые доработки с ручными действиями по реальной операционной модели;
- иметь короткий список того, что нельзя “закрыть коммитом”.

Важно:
- этот документ не заменяет персональную юридическую консультацию;
- если модель обработки данных меняется, checklist нужно проходить заново.

## 1. Operator disclosure

Проверить:
- в runtime заполнены реальные `OPERATOR_*` и `NEXT_PUBLIC_* disclosure` поля;
- bot и web показывают одни и те же реквизиты;
- privacy contact email реально работает.

Подтверждение:
- дата проверки;
- кто проверял;
- где именно открывались страницы и bot-документы.

## 2. Public legal pages

Проверить после актуального деплоя:
- `/privacy`
- `/terms`
- `/user-agreement`
- `/transborder-consent`
- `/marketing-consent`
- `/ai-policy`

Убедиться:
- нет `404` и redirect loop;
- тексты соответствуют текущей модели сервиса;
- policy URLs из `lead-bot` ведут на те же документы.

## 3. 152-ФЗ / operator position

Проверить по фактической модели:
- нужен ли отдельный шаг по уведомлению/обновлению позиции оператора;
- не поменялся ли состав обрабатываемых персональных данных;
- не изменилась ли цель обработки по сравнению с текущими документами.

Зафиксировать:
- принятое решение;
- дату;
- основание/комментарий.

## 4. Трансграничная передача

Проверить:
- соответствует ли текст согласия реальному использованию внешних AI/LLM сервисов;
- не изменился ли список processors/provider'ов;
- не нужно ли обновить wording и внутренние записи по трансграничной передаче.

Зафиксировать:
- какие внешние сервисы реально используются;
- что указано в документах;
- есть ли расхождение.

## 5. Retention policy

Проверить:
- соответствует ли runtime retention policy реальному регламенту хранения;
- не хранятся ли данные дольше, чем это описано в документах;
- понятен ли порядок удаления/экспорта/исправления данных.

## 6. Secret rotation

Проверить по [secret-rotation-checklist.md](./secret-rotation-checklist.md):
- какие ключи уже ротированы;
- какие ключи остаются legacy;
- есть ли дата следующего обязательного прохода.

## 7. Когда этот блок считается закрытым

Только если:
- runtime и публичные legal-документы согласованы;
- operator disclosure проверен живьем;
- policy URLs открываются;
- решение по `152-ФЗ / трансграничке / retention` зафиксировано как операционное, а не осталось “в уме”.
