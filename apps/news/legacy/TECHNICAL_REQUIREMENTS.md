## 🎯 2. Функциональные требования

### 2.1. Онбординг и профилирование пользователей

**Описание:**
При первом запуске `/start` бот проводит интерактивный опрос для создания профиля пользователя.

**Вопросы онбординга:**

1. **Юридические интересы** (множественный выбор):
   - 📊 Персональные данные (GDPR, ПДн)
   - 🤖 Искусственный интеллект и право
   - 💼 Корпоративное право и M&A
   - 💰 Криптовалюты и блокчейн
   - 📝 Интеллектуальная собственность
   - ⚖️ Судебная практика
   - 🏛️ Регуляторика и комплаенс
   - 🌐 Международное право
   - 🔒 Кибербезопасность
   - 📈 Налоговое право

2. **Уровень экспертизы**:
   - 🎓 Студент юрфака
   - ⚖️ Практикующий юрист
   - 🏢 In-house юрист
   - 💼 Бизнес-лидер / CEO
   - 📰 Журналист / исследователь
   - 🤝 Просто интересуюсь темой

3. **Географические интересы**:
   - 🇷🇺 Россия
   - 🇪🇺 Европейский союз
   - 🇺🇸 США
   - 🇨🇳 Китай
   - 🌍 Глобально (все юрисдикции)

4. **Формат контента** (предпочтения):
   - ⚡ Краткие новости (2-3 абзаца)
   - 📄 Полный анализ (подробные статьи)
   - 📊 С инфографикой и статистикой
   - 🎯 Только с практическими выводами
   - 🔗 С первоисточниками и ссылками

5. **Частота уведомлений**:
   - 🔥 Мгновенно (каждая новая статья)
   - 📅 Дайджест 1 раз в день
   - 📬 Дайджест 2-3 раза в неделю
   - 🔕 Без уведомлений (читаю сам)

**Технические детали:**
- Диалог реализован через FSM (Finite State Machine) в aiogram
- Данные сохраняются в новую таблицу `user_profiles`
- Пользователь может обновить профиль через `/settings_profile`
- Пропуск онбординга: кнопка "Пропустить, заполню потом"

**Структура БД - таблица `user_profiles`:**
```sql
CREATE TABLE user_profiles (
    id SERIAL PRIMARY KEY,
    user_id BIGINT UNIQUE NOT NULL,
    username VARCHAR(255),
    first_name VARCHAR(255),

    -- Профиль интересов (JSONB)
    legal_interests JSONB DEFAULT '[]',  -- ['gdpr', 'ai_law', 'corporate']
    expertise_level VARCHAR(50),          -- 'student', 'lawyer', 'inhouse', 'business', 'journalist', 'enthusiast'
    geo_interests JSONB DEFAULT '[]',    -- ['ru', 'eu', 'us', 'global']
    content_format VARCHAR(50),           -- 'short', 'full', 'infographic', 'practical', 'sourced'
    notification_frequency VARCHAR(50),   -- 'instant', 'daily', 'weekly', 'off'

    -- Метаданные
    onboarding_completed BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),

    -- Статистика поведения
    total_reads INTEGER DEFAULT 0,
    total_reactions INTEGER DEFAULT 0,
    last_activity TIMESTAMP
);
```

### 2.2. Персонализация новостной ленты

**Описание:**
На основе профиля пользователя настраивается персональная лента новостей.

**Механизм работы:**

1. **Фильтрация по интересам:**
   - Новости тегируются при AI-анализе (тема, юрисдикция, сложность)
   - Пользователю показываются только релевантные его профилю новости
   - Остальные доступны через "Показать все"

2. **Ранжирование:**
   - Топ ленты = новости, соответствующие 100% интересам
   - Ниже = частичное совпадение (50%+)
   - Внизу = "Может быть интересно" (тематически близкие)

3. **Адаптивное обучение:**
   - Отслеживание, какие статьи читает пользователь
   - Корректировка профиля на основе поведения
   - "Вы часто читаете про GDPR - добавить в интересы?"

**Команды:**
- `/feed` - Персональная лента (только мои темы)
- `/feed_all` - Все новости
- `/feed_today` - Сегодняшний дайджест
- `/feed_weekly` - Недельный обзор

**Таблица тегирования статей - расширение `post_drafts`:**
```sql
ALTER TABLE post_drafts ADD COLUMN tags JSONB DEFAULT '{}';
-- Пример: {"topics": ["gdpr", "ai_law"], "jurisdictions": ["eu", "ru"], "complexity": "medium"}
```

### 2.3. Интерактивная система фидбека

**Описание:**
Собираем обратную связь от читателей для улучшения качества контента.

**Варианты фидбека:**

1. **На опубликованной статье (в канале):**
   - Inline-кнопки под постом: 👍 Полезно | 👎 Не то | 💾 Сохранить
   - При нажатии открывается мини-опрос в боте

2. **В личном боте:**
   - После прочтения статьи (tracking через UTM):
     ```
     Эта статья была полезна?
     ✅ Да, очень!
     👌 Скорее да
     😐 Так себе
     ❌ Нет, не то
     ```

3. **Детальный фидбек** (при негативной оценке):
   ```
   Что можно улучшить?
   • Слишком длинная
   • Не хватает деталей
   • Неактуальная тема
   • Плохой AI-анализ
   • Нерелевантный источник
   ```

4. **Предложения тем:**
   ```
   /suggest <тема>

   Пример: /suggest регулирование ChatGPT в финансовом секторе
   ```

**Структура БД - таблица `user_feedback`:**
```sql
CREATE TABLE user_feedback (
    id SERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL,
    publication_id INTEGER REFERENCES publications(id),

    rating VARCHAR(20),  -- 'very_useful', 'useful', 'neutral', 'not_useful'
    issues JSONB,        -- ['too_long', 'lacks_details', 'irrelevant']
    comment TEXT,

    created_at TIMESTAMP DEFAULT NOW()
);
```

**Использование данных:**
- Автоматический отчет по quality score каждой статьи
- Коррекция AI-промптов на основе замечаний
- Черный список источников (если много негатива)

### 2.4. CRM-аналитика и сегментация

**Описание:**
Отслеживание поведения пользователей и сегментация аудитории.

**Метрики по пользователям:**

1. **Вовлеченность:**
   - Частота посещений бота
   - Количество прочитанных статей
   - Среднее время между визитами
   - Доля реакций (engagement rate)

2. **Предпочтения:**
   - Топ-3 темы по количеству прочтений
   - Любимые источники
   - Предпочитаемое время чтения

3. **Lifecycle стадии:**
   - **New** - только подписался (<3 дней, <5 прочтений)
   - **Active** - регулярно читает (7+ прочтений/неделю)
   - **Engaged** - читает + дает фидбек + рекомендует
   - **At Risk** - не заходил >7 дней
   - **Churned** - не заходил >30 дней

**Автоматические действия:**
- **At Risk → Реактивация:**
  Сообщение: "Вы давно не заходили! Вот что произошло за неделю: ..."

- **Engaged → VIP:**
  Предложение бета-тестирования новых функций

- **New → Онбординг:**
  Напоминание заполнить профиль через 3 дня

**Таблица БД - `user_analytics`:**
```sql
CREATE TABLE user_analytics (
    id SERIAL PRIMARY KEY,
    user_id BIGINT UNIQUE NOT NULL,

    -- Счетчики
    total_sessions INTEGER DEFAULT 0,
    total_articles_read INTEGER DEFAULT 0,
    total_reactions INTEGER DEFAULT 0,
    total_shares INTEGER DEFAULT 0,

    -- Поведение
    avg_session_duration INTEGER,        -- секунды
    favorite_topics JSONB DEFAULT '[]',  -- топ-3 темы
    favorite_sources JSONB DEFAULT '[]', -- топ-3 источника
    preferred_read_time TIME,            -- среднее время чтения

    -- Lifecycle
    lifecycle_stage VARCHAR(50),         -- 'new', 'active', 'engaged', 'at_risk', 'churned'
    first_seen TIMESTAMP,
    last_seen TIMESTAMP,
    last_reaction TIMESTAMP,

    -- Монетизация (будущее)
    is_premium BOOLEAN DEFAULT FALSE,
    ltv_estimate DECIMAL(10,2) DEFAULT 0,

    updated_at TIMESTAMP DEFAULT NOW()
);
```

**Команды для админа:**
- `/analytics_users` - Общая статистика по пользователям
- `/analytics_segments` - Распределение по сегментам
- `/analytics_churn` - Кто в зоне риска
- `/analytics_top_users` - Топ активных пользователей

### 2.5. AI-ассистент для работы с архивом

**Описание:**
Возможность задавать вопросы по всем опубликованным статьям через RAG (Retrieval-Augmented Generation).

**Функции:**

1. **Поиск по архиву:**
   ```
   /search GDPR штрафы 2025

   → Найдено 12 статей:
   1. "Meta оштрафовали на €1.2 млрд за GDPR" (12.05.2025)
   2. "Новые рекорды GDPR-штрафов в Q1 2025" (23.03.2025)
   ...
   ```

2. **Вопросы к AI:**
   ```
   /ask Какие основные изменения в регулировании ИИ произошли в ЕС за последний год?

   → [AI генерирует ответ на основе опубликованных статей с цитатами и ссылками]
   ```

3. **Сравнительный анализ:**
   ```
   /compare GDPR vs CCPA

   → [AI сравнивает регулирование на основе статей в архиве]
   ```

4. **Дайджесты:**
   ```
   /digest тема=ai_law период=месяц

   → Автоматический дайджест по теме за период
   ```

**Технология:**
- **Vector DB:** pgvector в PostgreSQL для эмбеддингов статей
- **Embeddings:** OpenAI text-embedding-3-small
- **LLM:** GPT-4 или Claude для генерации ответов
- **Context window:** топ-5 релевантных статей

**Таблица БД - `article_embeddings`:**
```sql
CREATE TABLE article_embeddings (
    id SERIAL PRIMARY KEY,
    publication_id INTEGER REFERENCES publications(id),

    -- Векторное представление
    content_embedding vector(1536),  -- OpenAI embedding
    title_embedding vector(1536),

    -- Метаданные для поиска
    text_content TEXT,               -- полный текст для контекста
    created_at TIMESTAMP DEFAULT NOW(),

    -- Индекс для векторного поиска
    INDEX ON content_embedding USING ivfflat (content_embedding vector_cosine_ops)
);
```
